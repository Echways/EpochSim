# Детерминизм

Избегайте недетерминированных источников внутри систем и обработчиков.

## Частые ошибки

- `DateTime.Now` / `DateTime.UtcNow`
- `Random` вместо `ctx.Rng`
- `Guid.NewGuid()` в логике симуляции
- зависимость от порядка обхода hash-коллекций
- скрытые гонки потоков, меняющие порядок событий
- неконтролируемое поведение с плавающей точкой

## Рекомендации

- использовать только `ctx.Rng` для доменной случайности
- держать обработчики команд/событий явными и контролируемыми по побочным эффектам
- сохранять `statefp.jsonl` для сравнения прогонов
- включать snapshots для быстрого детерминированного replay

## Контракт детерминизма

EpochSim гарантирует детерминированное выполнение при одинаковых входных данных (начальное состояние, seed, системы, команды/события, опции). Ниже фиксированные правила поведения.

### 1) Жизненный цикл запуска

- `OnRunStart` вызывается ровно один раз до начала обработки тиков.
- `OnRunEnd` вызывается всегда и ровно один раз, даже при ошибке.
- Если происходит исключение, `OnRunFailed` вызывается один раз перед повторным выбросом.

### 2) Порядок тиков

- Для каждого тика `T` сначала вызывается `OnTickStart(T)`.
- Никакие события тика `T` не диспетчатся до `OnTickStart(T)`.
- После завершения обработки команд/событий вызывается `OnTickEnd(T)`.

### 3) Порядок систем

- Системы тикаются в порядке регистрации.
- Для каждой системы `OnSystemTickStart(T, system)` и `OnSystemTickEnd(T, system)` обрамляют вызов `Tick`.
- Обработка событий (`Handle`) тоже идёт в порядке регистрации систем.

### 4) Правила планировщика

- За тик `T` обрабатываются только события, запланированные на `T`.
- События, запланированные на один и тот же тик, обрабатываются в порядке добавления (стабильная очередь).
- События за пределами `endTickInclusive` не диспетчатся.

### 5) Pump-цикл команд/событий

Внутри каждого тика движок повторяет шаги, пока обе очереди не пусты:

1. Сливает и обрабатывает все команды (FIFO), добавляя события в очередь.
2. Сливает и обрабатывает все события (FIFO) для всех систем в порядке регистрации.

### 6) Порядок middleware

- Все callbacks middleware вызываются в порядке регистрации для каждого hook.
- Порядок `OnRunStart` -> тики -> `OnRunEnd` стабилен.
- `OnRunFailed` вызывается ровно один раз.

Любое отклонение от этих правил считается регрессией корректности.
